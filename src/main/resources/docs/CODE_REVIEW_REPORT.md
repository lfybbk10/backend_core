## Issue #1: Неверный выбор HTTP-метода

**Приоритет:** CRITICAL
**Местоположение:** InviteeController.java, строка 24, 
метод ```public List<Invitee> getInvitees()```

**Что плохо:**
Используется метод Post для получения данных 

**Почему плохо:**
Нарушение семантических стандартов HTTP-методов

**Как исправить:**
Заменить аннотацию @PostMapping на аннотацию @GetMapping

## Issue #3: Entity вместо DTO

**Приоритет:** CRITICAL
**Местоположение:** InviteeController.java, все методы контроллера

**Что плохо:**
Методы контроллера возвращают entity вместо dto сущности

**Почему плохо:**
Нарушение security и увеличение performance из-за лишних данных

**Как исправить:**
Создать DTO-сущности для request и response, и встроить их в методы контроллера вместо чистых entity

## Issue #5: SQL инъекция

**Приоритет:** CRITICAL
**Местоположение:** InviteeController.java, строка 42,
метод ```public Invitee create(@RequestBody Map<String, Object> params)```

**Что плохо:**

**Почему плохо:**

Использовать Spring Data JPA метод или PreparedStatement

## Issue #7: Missing authorization checks

**Приоритет:** CRITICAL
**Местоположение:** InviteeController.java, строка 56,
метод ```public Invitee delete(@PathVariable UUID id)```

**Что плохо:**
Нет проверки авторизации на методе удаления

**Почему плохо:**
Любой user может выполнить метод удаления любого id

**Как исправить:**
Добавить аннотацию @PreAuthorize для проверки роли пользователя

## Issue #9: 500 на бизнес-ошибки вместо 4xx

## Issue #11: Бизнес-логика в контроллере

метод ```public Invitee create(@RequestBody Map<String, Object> params)```
